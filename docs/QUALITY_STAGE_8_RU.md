# Этап 8. Качество кода и автоматизированные тесты

Этап 8 завершает минимальный профессиональный контур frontend-проекта. Статические проверки,
unit-тесты, component-тесты, браузерные сценарии и production build объединены одной командой:

```bash
npm run quality
```

## Что настроено

-   ESLint 9 с flat config и Nuxt-правилами;
-   Prettier с отдельными командами проверки и форматирования;
-   строгий TypeScript;
-   дополнительная проверка `noUncheckedIndexedAccess`;
-   отдельный `npm run typecheck`;
-   Vitest в Nuxt-окружении;
-   Vue Test Utils и Nuxt Test Utils для компонентов;
-   Playwright с Chromium и автоматическим запуском Nuxt dev server;
-   игнорирование отчётов и временных результатов тестов в Git.

Проверка типов вынесена в отдельную команду. Это делает quality gate явным и не замедляет каждую
локальную production-сборку скрытой повторной проверкой.

## Unit-тесты

Добавлено 15 тестов для Pinia stores и mock services.

### Conversations store

Проверяются:

-   открытие доступного разговора;
-   сброс персонального unread при открытии;
-   запрет перехода в недоступный пользователю канал;
-   создание канала и дедупликация участников;
-   выбор персонального чата с Demo Bot после смены пользователя;
-   добавление и удаление участников;
-   запрет удалить текущего пользователя из группы.

### Messages store

Проверяются:

-   создание сообщения и обновление `lastMessageId`;
-   персональные unread-счётчики;
-   асинхронная отправка и состояние sending;
-   права на редактирование и удаление;
-   обновление последнего сообщения после удаления;
-   добавление и снятие reactions без дубликатов.

### Mock services

Проверяются:

-   задержка и детерминированные ответы Demo Bot;
-   корректное совпадение ключевых слов по границам слов;
-   seed при первом запуске;
-   сохранение и повторное чтение snapshot;
-   исключение временных `blob:` URL из постоянного хранилища;
-   mock-ошибки;
-   восстановление исходных данных через reset.

Во время создания тестов был найден и исправлен реальный дефект mock-бота: короткое ключевое слово
`hi` совпадало внутри слов `which` и `technologies`. Теперь ключевые слова распознаются только по
границам слов.

## Component-тесты

Добавлено 4 теста критичных UI-элементов:

-   `ChannelItem` — активное состояние, unread, доступное имя и событие выбора;
-   `ReactionButton` — `aria-pressed`, доступное действие, событие и завершение анимации;
-   `Avatar` — fallback на инициалы, presence status и `alt` изображения.

Эти тесты проверяют не внутреннюю реализацию компонентов, а видимый контракт: props, DOM,
доступность и пользовательское действие.

## Playwright E2E

Добавлены семь сценариев:

1. Открыть личный диалог и отправить сообщение.
2. Создать канал и выбрать участника.
3. Переключить mock-пользователя и пересчитать доступные разговоры.
4. Отправить сообщение, перезагрузить страницу и проверить сохранение.
5. Изменить demo data и восстановить seed кнопкой **Reset demo data**.
6. Показать onboarding только при первом посещении.
7. Проверить отсутствие горизонтального переполнения чата и composer на ширине 320 px.

Каждый тест начинает работу с чистого `localStorage`. Сценарии независимы друг от друга и
используют доступные роли и имена элементов вместо хрупких координат или CSS-структуры.

## Команды

```bash
npm run format          # применить форматирование
npm run format:check    # проверить форматирование
npm run lint            # проверить ESLint
npm run lint:fix        # применить безопасные ESLint-исправления
npm run typecheck       # строгая проверка TypeScript/Vue
npm run test:unit       # unit-тесты stores и services
npm run test:components # component-тесты
npm run test:e2e        # семь Playwright-сценариев
npm run test:e2e:ui     # интерактивный Playwright UI
npm run quality         # весь контур и production build
```

Перед первым Playwright-запуском:

```bash
npx playwright install chromium
```

## Что это показывает в резюме

Проект демонстрирует не только разработку интерфейса, но и инженерный контроль качества:

-   проектирование тестируемой frontend-архитектуры;
-   unit-тестирование бизнес-правил Pinia;
-   component-тестирование Vue и accessibility-контрактов;
-   end-to-end проверку ключевых пользовательских путей;
-   строгую типизацию;
-   воспроизводимое форматирование и linting;
-   единый quality gate перед публикацией.

Краткая формулировка для резюме:

> Настроил профессиональный quality-контур Nuxt/Vue-приложения: strict TypeScript, ESLint,
> Prettier, unit- и component-тесты на Vitest, а также Playwright E2E для отправки сообщений,
> создания каналов, смены пользователя, localStorage persistence и reset demo data.

## Граница текущего этапа

Приложение сохраняет исходную версию Nuxt 3, на которой был создан проект. `npm audit` показывает
advisory в старом Nuxt/Vite toolchain. Автоматический `npm audit fix` упирается в несовместимые peer
requirements новых Nuxt Test Utils и Vitest, поэтому принудительный `--force` не применялся.
Обновление Nuxt/Vite/Vitest следует выполнить отдельным этапом с миграцией и повторным полным
регрессионным прогоном.
